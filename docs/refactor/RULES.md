# Listening rules, use cases, and existing test evidence

Read this against [THE RULES OF MUSIC LISTENING](../../THE%20RULES%20OF%20MUSIC%20LISTENING.md).
Section references below use that document's numbering. **Implemented** means a
routine provides the stated operation, not that all nearby prose is automated.
**Partial/manual** means a human still supplies listening, timing, choices, or
playlist events. **Legacy** means supported code for the discontinued main-list
workflow. No missing product features are added by the refactor.

Each test reference is an existing file; named tests are particularly useful
behavior anchors. They do not imply complete edge-case or branch coverage.
Item 2 must add characterization around the identified gaps before moving code.

## Differences to preserve and review separately

1. Prose says “>50%” in §1.5. The live keep calculation floors the product and
   uses at least one like for a nonempty album at a positive threshold; three
   tracks with one like can be kept. Existing tests make this explicit.
2. Prose says start discography queues with Newfoundland. A fresh implementation
   state starts with `requeue`, and its existing test asserts this.
3. The general Random.org prose describes page selection from minute digits;
   Blast from the Past also has a seventh-page/hour condition. Palace/discography
   historical selection uses seconds only for rank. Do not unify these policies.
4. “Skip after three unliked tracks” has implementation-specific liked-tail
   handling; New Kids tests explicitly jump to the next liked track. Canonical
   album endpoints also truncate New Wine evaluation and trigger completion.
5. New Kids zero-like handling can override saved-release promotion. Treat the
   existing assessment tests as the baseline rather than only the prose OR list.
6. Palace fills an alphabetical stream as well as the historical stream; the
   Friday prose does not fully describe that existing command behavior.
7. Last.fm recommendations and release discovery reconstruct goals using APIs;
   they do not promise an identical ordering to Last.fm's personal website.

This inventory records discrepancies without resolving them. A rule change must
have its own reviewed expected behavior instead of being disguised as refactoring.
